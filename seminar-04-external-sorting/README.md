# Семинар 4. Внешние сортировки и unit-тесты на C++

Дисциплина: Алгоритмы и структуры данных.

## Что реализовано

Три алгоритма внешней сортировки, каждый оформлен отдельной библиотекой (пара файлов `.h` + `.cpp`):

| Алгоритм | Функции | Файлы |
|---|---|---|
| Двухфазная сортировка простым слиянием | `twoPhaseMergeSortFile`, `twoPhaseMergeSort` | `two_phase_merge_sort.h / .cpp` |
| Однофазная сортировка простым слиянием | `onePhaseMergeSortFile`, `onePhaseMergeSort` | `one_phase_merge_sort.h / .cpp` |
| Естественная сортировка слиянием | `naturalMergeSortFile`, `naturalMergeSort` | `natural_merge_sort.h / .cpp` |

У каждой сортировки две шаблонные функции:

```cpp
// Сортирует значения типа T, записанные в текстовом файле
template <typename T>
void twoPhaseMergeSortFile(const std::string& fileName);

// Сортирует массив: записывает его во временный файл, сортирует файл, считывает обратно
template <typename T>
void twoPhaseMergeSort(T* array, int size);
```

Объявления шаблонов находятся в `.h`, реализация в `.cpp`. В конце каждого `.cpp` выполнено явное инстанцирование для типов `int`, `long long`, `float`, `double`, `std::string`.

Данные хранятся в текстовых файлах: значения разделены пробелами или переводами строк, чтение и запись выполняются операторами `>>` и `<<`. Поэтому строки `std::string` должны быть непустыми и без пробелов.

## Описание алгоритмов

- **Двухфазная сортировка простым слиянием.** Три файла: исходный A и вспомогательные B, C. Каждый проход - две фазы: распределение серий длины k из A по B и C, затем слияние пар серий из B и C обратно в A сериями длины 2k. Длина серии: 1, 2, 4, 8, ...
- **Однофазная сортировка простым слиянием.** Четыре вспомогательных файла. Распределение объединено со слиянием: слитые серии сразу записываются по очереди в два выходных файла, после прохода входные и выходные файлы меняются ролями. Перезаписей данных примерно вдвое меньше, чем в двухфазной.
- **Естественная сортировка слиянием.** Как двухфазная, но вместо серий фиксированной длины используются естественные серии - уже упорядоченные участки данных. Проходы повторяются, пока в файле не останется одна серия. На частично упорядоченных данных проходов меньше.

## Временные файлы

- При сортировке файла `name` создаются вспомогательные файлы `name.b.tmp`, `name.c.tmp` (у однофазной сортировки ещё `name.a.tmp` и `name.d.tmp`). После сортировки они удаляются.
- При сортировке массива создаётся временный файл вида `two_phase_merge_sort_1.tmp` в текущей папке. После сортировки он удаляется.
- Если файл не удалось открыть, выбрасывается исключение `std::runtime_error`.

## Структура

```
ExternalSorting.sln        решение Visual Studio (два проекта)
external_sorting/          проект ExternalSorting - статическая библиотека с сортировками
    include/               заголовочные файлы
    src/                   файлы реализации
tests/                     проект Tests - unit-тесты
    test_sorts.cpp         тесты всех трёх сортировок
```

Библиотека тестирования Catch2 лежит в корне репозитория в папке `catch2/` и общая для всех семинаров.

## Тесты

Используется Catch2. Для каждой сортировки написано 22 теста (всего 66) по схеме Arrange - Act - Assert.

Обработка данных в памяти (сортировка массива), 14 тестов: массив из варианта 13 `[11, 7, 14, 20, 5, 1, 15, 9]`, пустой массив, нулевой указатель, один элемент, два элемента, уже отсортированный массив, массив в обратном порядке, дубликаты и отрицательные числа, одинаковые элементы, тип `double`, тип `std::string`, сравнение с `std::sort` на 1000 элементах, размер не степень двойки, массив из готовых серий.

Слияние временных файлов (сортировка файла), 8 тестов: файл с массивом из варианта 13, пустой файл, файл с одним значением, файл в обратном порядке, значения `double` без потери точности, сравнение с `std::sort` на файле из 1000 значений, удаление вспомогательных файлов после сортировки, исключение при отсутствии файла.

## Запуск

Открыть `ExternalSorting.sln` в Visual Studio и собрать решение (Ctrl+Shift+B). Тесты запускаются автоматически после сборки проекта Tests (событие после сборки `"$(TargetPath)"`), результат выводится в окно «Вывод».
