# Лабораторная работа № 1 — вариант 13

**Обработка строки символов различными способами хранения.**

Найти самое длинное слово в строке и удалить его, если оно содержит более
5 символов и не начинается с гласной буквы.

## Принятые правила

- Поддерживаются русские и английские буквы, оба регистра, включая Ё/ё.
- Кодировка исходного текста и файлов — UTF-8. Длина слова считается в буквах,
  а позиции и длина массива — в байтах. Например, `книга` — 5 букв и 10 байтов:
  это слово не удаляется.
- Слово — непрерывная последовательность русских и английских букв.
  Пробелы, табуляция, цифры, дефисы и пунктуация разделяют слова.
  Это явно выбранное правило для неоднозначной части задания.
- Если самых длинных слов несколько, выбирается **первое**.
- Сначала выбирается самое длинное слово среди ВСЕХ слов, и только потом
  проверяется условие удаления. В `elephant planet` ничего не удаляется.
- Английские гласные: A, E, I, O, U; Y здесь считается согласной.
  Русские: А, Е, Ё, И, О, У, Ы, Э, Ю, Я. Й — согласная.
- Удаляются только буквы выбранного слова. Пробелы и пунктуация сохраняются.
  `Моя машина тут` превращается в `Моя  тут` с двумя пробелами.
- Ввод — одна текстовая строка без встроенного нулевого символа, до 1023 байтов
  UTF-8. Перевод строки не включается в результат; следующая строка не обрабатывается.
  Пустой ввод допустим. Превышение размера приводит к ошибке, а не обработке обрезка.
- Предполагается корректная кодировка UTF-8. Некорректные байты не относятся к
  поддерживаемому вводу; декодер безопасно пропускает их как разделители.
- Неанглийские и нерусские буквы также являются разделителями.

Эти уточнения не приписываются преподавателю: в условии они не определены.

## Что находится в решении

| Проект | Назначение |
|---|---|
| ArrayProgram | Программа 1: `char[]` + отдельная длина, конец массива не определяется по `\0` |
| CStringProgram | Программа 2: C-строка, поиск и удаление до `\0` |
| FileProgram | Программа 3: чтение из файла, обработка по варианту 2, запись в другой файл |
| StringCore | Общие функции и две отдельные реализации обработки |
| Tests | Catch2, автозапуск после сборки проекта тестов |

Три проекта Application дают три самостоятельные программы. StringCore —
вспомогательная статическая библиотека, Tests — отдельная тестовая программа.

`include/strings.h` содержит объявления и договорённости функций.
`src/strings.cpp` содержит реализацию. В `apps` находятся три функции `main`,
каждая — в своём проекте. `tests/test_strings.cpp` проверяет обработку и файловый ввод/вывод.

В каждой рабочей программе для строки используется ровно один массив.
В алгоритмах нет `std::string`, `std::vector`, копии строки, массива слов или
временного массива для удаления. Дополнительные переменные — индексы, указатели
и декодируемый символ. Строки с ожидаемыми ответами в тестах не участвуют в алгоритме.

## Как запустить в Visual Studio

1. Распаковать архив. Внутри лежат `lab-01-strings` и резервная копия `catch2`.
2. Для добавления в существующий репозиторий скопировать **только** папку
   `lab-01-strings` рядом с `seminar-01-sorting`, `seminar-02-enhanced-sorting`
   и остальными семинарами. Общая папка `catch2` в репозитории уже есть.
   Для самостоятельного запуска оставить две папки из архива рядом.
3. Открыть `lab-01-strings/Lab01Strings.sln`.
4. Выбрать `Debug | x64`, собрать решение: Ctrl+Shift+B.
5. Тесты автоматически запустятся после сборки проекта Tests.
   Их также можно запустить отдельно: выбрать Tests запускаемым проектом,
   затем Ctrl+F5.
6. Для нужного варианта выбрать ArrayProgram, CStringProgram или FileProgram
   через «Назначить запускаемым проектом» и нажать Ctrl+F5.

Для FileProgram рабочий каталог настроен на папку решения. В ней уже есть
`input.txt`; результат появится в `output.txt`. Входной файл сохраняйте как UTF-8.
Из командной строки можно задать другие пути:

```text
FileProgram.exe input.txt output.txt
```

Функции `fopen`, `fgets`, `fputs`, `fclose` реализуют файловый вариант.
Для файлов и перенаправленного ввода первый вариант использует `fgetc`,
второй — `fgets`. В интерактивной консоли Windows оба варианта читают
символы через `ReadConsoleW`: каждый символ сразу кодируется в UTF-8
в исходном массиве, без дополнительного массива. Это предотвращает замену
русских букв нулевыми байтами при узком консольном вводе CRT.
В C-строке после чтения устанавливается завершающий ноль.
[Описание ReadConsoleW у Microsoft](https://learn.microsoft.com/en-us/windows/console/readconsole).
Терминал может дополнительно ограничивать длину редактируемой строки.
Настройка Windows-консоли переключает ввод и вывод на UTF-8.

Если нет доступного набора инструментов C++, установите компонент Visual Studio
«Разработка классических приложений на C++». Проект использует установленный
набор инструментов по умолчанию и стандарт C++17.

## Алгоритм и объяснение для защиты

1. Идём по исходной строке слева направо.
2. Разделители пропускаем. У слова запоминаем начало и первую букву.
3. Считаем буквы слова. Русскую букву UTF-8 нельзя считать как два символа.
4. Если слово длиннее сохранённого максимума, обновляем начало, конец, длину
   и первую букву. Используем `>`, а не `>=`, поэтому при равенстве остаётся первое.
5. После просмотра всей строки проверяем `длина > 5` и `первая буква не гласная`.
6. Если оба условия выполнены, сдвигаем хвост строки влево на число байтов слова.

В **массиве** цикл заканчивается по `pos < length`, при удалении уменьшаем `length`.
Нулевой терминатор не читается и не записывается. Печатаем ровно `length` байтов.

В **C-строке** цикл заканчивается по `*pos != '\0'`. При удалении переносим хвост
вместе с нулём, чтобы новая строка также корректно завершалась.

В **файловой программе** открываем вход, читаем строку в единственный массив,
закрываем вход, вызываем обработку C-строки, затем открываем выход и сохраняем
результат. Если вход не удалось прочитать или строка слишком длинная, выходной
файл не открывается и не перезаписывается. Один и тот же входной и выходной файл
отклоняется. Уже существующий отдельный выходной файл заменяется результатом.

Сложность: O(n) по числу байтов, дополнительная память обработки O(1).
Декодирование одного символа читает не более четырёх байтов.

Пример: `кот машина дом`

- `кот` — 3 буквы, текущий максимум;
- `машина` — 6 букв, новый максимум;
- `дом` — 3 буквы, максимум прежний;
- 6 > 5, `м` не гласная — удаляем байты `машина`;
- получаем `кот  дом`.

UTF-8 — причина появления вспомогательного декодера. Он не создаёт новую строку:
по нескольким байтам получает числовой код одной буквы и ширину этого символа.
Основной алгоритм остаётся обычным поиском максимума и сдвигом хвоста.

## Тестирование

Методика: подготовка исходных данных → вызов функции → сравнение с заранее
заданным результатом. Ожидаемые ответы не вычисляются проверяемым алгоритмом.

Основные сценарии перечислены в `TEST_CASES.md`. Автоматические тесты Catch2
покрывают оба алгоритма, оба способа чтения и файловую обработку. Дополнительный
скрипт проверяет три готовые программы целиком, включая `main` и коды завершения:

```text
python tests/test_cli.py x64/Debug
```

Сбой физического диска и отказ записи при закрытии файла не имитируются;
соответствующие результаты стандартных функций в коде проверяются.
Процент покрытия строк/ветвей не измерялся — наличие тестов не означает 100%.

## Ошибки

| Код | Значение |
|---|---|
| 1 | Строка превышает допустимый размер |
| 2 | Ошибка чтения или закрытия входа |
| 3 | Не удалось открыть входной файл |
| 4 | Не удалось открыть выходной файл |
| 5 | Ошибка записи или закрытия выхода |
| 6 | Вход и выход указывают на один файл |

Любая ошибка завершает программу с кодом 1. Успех — код 0.

## Проверка именно консоли Windows

После сборки откройте терминал в папке лабораторной и выполните:

```text
x64\Debug\Tests.exe "[console]"
```

Это отдельный скрытый тест Catch2, потому что автоматический запуск после сборки
использует перенаправленные потоки. Он подаёт русские и английские символы
через очередь консольного ввода, проверяет UTF-8, пустую строку и переполнение
на границах многобайтовых символов. В тесте 273 проверки, все прошли.
